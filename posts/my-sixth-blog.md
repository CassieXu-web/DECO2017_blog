Accessibility is not only about following rules. It is also about making a website easier for different people to use in different situations. At this stage of my Vintarchive prototype, I used WCAG accessibility principles, usability testing, and technical reflection to evaluate my website. My main goal was to see whether users could move through the website clearly and complete key actions, such as browsing exhibitions, viewing item details, logging in, saving items, and managing their own profile.

The main accessibility framework I used was WCAG, especially the four POUR principles: Perceivable, Operable, Understandable and Robust. For my website, “Perceivable” means that users should be able to clearly see important content such as item images, prices, tags, descriptions, and exhibition information. Because my website uses a brown vintage colour palette, I need to make sure the text is still easy to read and has enough contrast. I also need to add meaningful alt text for images, so users can still understand the content if they use a screen reader or if the image does not load.

“Operable” means users should be able to use the website easily, not only with a mouse. This is important for my exhibition page, because users enter exhibitions by clicking on door-like elements. At first, I focused more on the hover effect because it looked interesting. However, I realised that hover alone is not enough, because some users may use a touchscreen or keyboard. In the future, these interactions should also work through clicking, tapping, and keyboard navigation.

“Understandable” is about whether the website is easy to follow. VintaArchive has different parts, including exhibitions, marketplace listings, item detail pages, forms, and profile pages. Therefore, users need to clearly understand where they are and what they can do next. Clear buttons, simple labels, and useful feedback messages are important. “Robust” means the website should work reliably across different browsers and devices. To support this, I need to use semantic HTML, consistent templates, and clearer form structures.

My testing goal was to find practical problems that could affect real users, instead of only checking whether the website looked finished. I followed a simple testing process. First, I looked through the website visually and checked the layout, spacing, text hierarchy, and labels. Second, I clicked through the main pages to test whether the navigation worked smoothly. Third, I checked accessibility issues, including image loading, alt text, heading structure, colour contrast, and button clarity. Finally, I tested some functional parts, especially registration, login, logout, likes, and saved items.

One important technical part of my prototype was the **cookie-based login system**. Since Vintarchive includes personal features, such as liked items, saved items, uploaded items, and profile content, the website needs to know which user is currently logged in. When a user registers, their email is saved in the database. If another user tries to register with the same email, the system rejects it. This helps avoid duplicate accounts and keeps the data more organised. Cookies are used to keep the user logged in, so the website can show personalised content. After users log out and log back in, their liked and saved items can still be shown because the information is stored in the database, not just temporarily on the page.

The testing results showed that the overall concept and visual style were clear, but there are still some areas to improve. Some images need better alt text and fallback states. The navigation bar also needs clearer hover and active states, so users can easily know which page they are on. The item cards could also be improved with more consistent spacing and clearer labels for price, trade type, and tags. From a usability perspective, users can understand the vintage theme, but some actions, such as “barter” or “save”, should be explained more clearly.

For future development, I would improve the website in four main ways. First, I would improve accessibility by adding alt text, checking colour contrast, and making sure the website can be used with a keyboard. Second, I would improve the login system with clearer error messages and safer session handling. Third, I would use analytics to understand user behaviour, such as which exhibitions users enter most, which categories they view, and where they leave the website. This would help me decide which parts of the website need more improvement. Finally, I would continue improving the responsive layout, because many users may browse vintage items on their phones.

Overall, this testing process helped me understand that accessibility and usability are not just final checklist tasks. They should be considered throughout the whole design and development process. A good web app should not only look visually interesting, but also be easy to use, reliable, and inclusive for different users.
