VintaArchive is a Sydney-based vintage platform that combines themed exhibitions with marketplace. The project was designed to help users discover, share, and exchange vintage objects through storytelling. Rather than treating vintage objects only as second-hand products, VintaArchive frames them as personal memories and cultural traces. This final reflection evaluates the website through performance, user experience, accessibility, functional requirements, and lessons learned during development.

During A2, our focus was mainly on building the core structure of the website and translating our original concept into a working prototype. The final website includes three main areas: Exhibition, Marketplace and Profile. The Exhibition section uses a row of doors as the main interaction. Each door represents a themed exhibition, with a door plate showing the exhibition name and a framed poster beside it. The Marketplace section allows users to browse vintage items through search and category tags. The Profile section supports account-related content, including published items, wishlist and orders. In A3, my focus shifted from planning and decision-making to evaluation and reflection.

One important iteration during development was the Marketplace filtering system. In the earlier version, all category tags were displayed together in one large group. Although this gave users many filtering options, the interface felt visually cluttered and made it difficult for users to quickly decide which tag to select. Based on this issue, we reorganised the tags into two clearer groups: Object Type and Era. This iteration reduced cognitive load and made the filtering system easier to scan, helping users browse marketplace items more efficiently. 

![tags iteration](/DECO2017_blog/assets/images/tags.jpg)

After completing the website, I used **Lighthouse** to evaluate the technical performance and accessibility of the website. Overall, the desktop result was stronger than the mobile result, which showed that the prototype still needs improvement in responsive design. The Lighthouse report showed strong scores in Accessibility, Best Practices and SEO, but the Performance score was lower. This was useful because it revealed that the main technical weakness of VintaArchive was not whether the interface could function, but how efficiently the visual content loaded, especially in a mobile testing environment.

![Lighthouse Analysis](/DECO2017_blog/assets/images/lighthouse1.png)

The **Performance** result showed that the page had a **high LCP (Largest Contentful Paint) value**. This means the largest visible element on the page took too long to load. In the context of VintaArchive, this result makes sense because the website relies heavily on visual assets, including vintage item images, textured backgrounds and decorative elements. These images increase the weight of the page and can slow down loading, especially on mobile or slower networks. In future development, I would reduce unused CSS, compress large images, convert key images to WebP format, and set explicit width and height values for images to prevent unstable loading. 

![LCP insight](/DECO2017_blog/assets/images/lcpsight.png)

**Accessibility** was one of the stronger areas of the Lighthouse report, but I did not treat a high score as proof that the website was fully accessible. Lighthouse identified that some background and foreground colours do not have a sufficient contrast ratio. This issue is closely connected to my visual direction. VintaArchive uses a warm brown, beige and low-saturation vintage colour palette to create an elegant and nostalgic atmosphere. While this colour system supports the brand identity, some text and interface elements may not stand out clearly enough against the background. This can affect **readability**, especially for smaller labels, navigation text, item information and buttons. In future iterations, I would keep the vintage palette but increase the contrast of functional text. I would check key colour combinations against WCAG AA contrast requirements.

Another accessibility issue is **keyboard interaction**. The Exhibition doors are visually memorable, but they rely strongly on hover. This works well for mouse users because the door opens when the cursor moves over it. However, keyboard users cannot hover, and mobile users also do not experience hover in the same way. If the doors are not keyboard focusable, some users may not be able to enter the exhibitions easily. In future development, I would add visible focus states, make the tab order logical, and ensure users can press Enter to enter an exhibition. The hover animation should also be paired with a focus-visible state, so keyboard users receive similar feedback. This would help make the creative interaction more inclusive while keeping the same visual concept.

**Responsive design** also needs further improvement. Some elements, such as the navigation bar, search field, marketplace tags, and exhibition doors, may compete for space on mobile. This is especially important because the Lighthouse mobile audit suggested weaker performance and because hover-based interactions do not translate well to touch screens. In future iterations, I would design a separate mobile layout rather than simply shrinking the desktop interface. For example, the exhibition doors could become vertically stacked exhibition cards, each with a poster, title, short description and clear “Enter Exhibition” button. The Marketplace filters could also collapse into grouped filter sections, making the search experience easier on smaller screens.

In addition to Lighthouse, we also conducted **user testing** after completing the website. Users responded positively to the overall colour palette and visual style, describing the website as warm, vintage and distinctive. However, users also identified several usability issues. One piece of feedback was that the Add an Item function was not obvious enough. To improve this, I would make the Add an Item button more visually prominent, place it consistently within exhibition pages, and add a short prompt explaining that users can contribute their own vintage object and story.

Looking back at the original functional requirements, most of the core prototype goals were achieved. The final version includes themed exhibitions, exhibition entry interactions, item browsing, an Add an Item flow, marketplace browsing, search and tag filtering, item cards, and profile-related pages. These functions successfully demonstrate the main concept of a vintage archive and marketplace. However, some planned features were not fully implemented, such as a complete payment system, direct messaging, advanced seller interactions, and fully persistent order management. In retrospect, the original scope was too ambitious because VintaArchive was trying to be both a curatorial archive and a full marketplace platform. For this prototype stage, it was more realistic to prioritise the exhibition experience, item contribution, and marketplace browsing rather than building a complete transaction system.

The main lesson I learned is that a strong visual concept needs to be balanced with usability, accessibility and technical performance. The vintage doors, textured backgrounds and warm colour palette helped create a distinctive identity, but they also introduced challenges such as slow image loading, low colour contrast, hover dependency and mobile layout issues. I also learned that evaluation should not happen only at the end. Lighthouse and WCAG-related checks should be introduced earlier in the design process, especially when choosing colours, designing interactions, and building responsive layouts. If accessibility had been tested earlier, I could have adjusted contrast, focus states and mobile behaviours before the final stage.

Overall, VintaArchive achieved its main conceptual goal: it transformed vintage browsing into a more emotional and story-driven experience. However, the evaluation showed that the same design decisions that made the website visually distinctive also created technical and accessibility challenges. If I continued developing VintaArchive, I would focus less on adding new features and more on improving the reliability of the existing core flows. My next priorities would be image optimisation, stronger mobile responsiveness, clearer Add an Item affordance, improved colour contrast, keyboard-accessible exhibition doors, and more structured user feedback after form submission. This project helped me understand that web development is not only about making an interface work, but about evaluating how well it performs for different users, devices and contexts.
